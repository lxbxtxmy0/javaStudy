Вот корректно сформулированная задача для ООП-проекта на Java — калькулятор, работающий с римскими и арабскими цифрами:
Задача: Реализация ООП-калькулятора с поддержкой арабских и римских чисел
Создайте класс Calculator, который поддерживает базовые арифметические операции (сложение, вычитание, умножение, деление) над числами в двух форматах: арабскими (1, 2, 3, …) и римскими (I, II, III, …).
Требования:
Класс Calculator должен иметь методы:
java
1
где:
operand1, operand2 — строки, представляющие числа (например, "12", "V", "X")
operator — один из: "+", "-", "*", "/"
Поддержка форматов:
Числа могут быть переданы в арабском (1–39) или римском (I–XXXIX) формате.
Важно: в одном выражении оба операнда должны быть в одном формате (оба арабские или оба римские). Иначе — выбросить исключение IllegalArgumentException с сообщением "Нельзя смешивать арабские и римские числа".
Ограничения:
Римские числа поддерживаются только в диапазоне I (1) до XXXIX (39).
Арабские числа — от 1 до 39.
Результат операции должен быть в том же формате, что и операнды.
Деление — целочисленное (остаток отбрасывается).
Результат не может быть меньше 1 (для римских чисел). Если результат ≤ 0 — выбросить IllegalArgumentException с сообщением "Результат не может быть нулевым или отрицательным".
Вспомогательные классы (рекомендуется):
ArabicNumeral — для парсинга и преобразования арабских чисел.
RomanNumeral — для парсинга, валидации и преобразования римских чисел (включая методы toArabic() и fromArabic(int)).
Примеры:
calculate("V", "+", "III") → "VIII"
calculate("10", "*", "3") → "30"
calculate("X", "/", "III") → "III" (10 / 3 = 3)
calculate("V", "+", "10") → IllegalArgumentException: Нельзя смешивать арабские и римские числа
calculate("I", "-", "II") → IllegalArgumentException: Результат не может быть нулевым или отрицательным
Тестирование:
Напишите юнит-тесты (JUnit) для проверки всех операций, граничных значений и ошибочных сценариев.
Дополнительные требования (по желанию):
Использовать enum для операторов.
Поддержка ввода с пробелами (например, " V + III ").
Логирование ошибок (необязательно, но полезно для продакшена).
Эта задача отлично подходит для отработки принципов ООП: инкапсуляция, полиморфизм, разделение ответственности, обработка исключений и работа с типами данных.
